# Mirror Puppet — handoff

Read this first. It is the complete state of the project as of 2026-09-11.

## What it is

A single-file web app: the camera picture → MediaPipe recognition (face 478 points + 52 expression
values, two hands × 21 points, body 33 points, all with depth) → a 2D skeleton drawn over the picture
and a 3D puppet of joints and bones (three.js) that mirrors the person and can be orbited.

- Live: https://nikolovarch01-cmd.github.io/mirror-puppet/ (GitHub Pages from this repo, branch `main`;
  `index.html` redirects to `mirror-puppet.html`). Every push to `main` redeploys in about a minute.
- Owner: Mihail Nikolov, architect. He talks Bulgarian; **the UI must stay in English** (he shares it).
- No build step, no bundler, no framework. Everything lives in `mirror-puppet.html`.

## Stack (all pinned, all checked live)

- `@mediapipe/tasks-vision` **1.0.1** from jsdelivr (`vision_bundle.mjs`; wasm from `/wasm`).
- `three` **0.186.0** via importmap; `OrbitControls` from `examples/jsm`.
- Models from `storage.googleapis.com/mediapipe-models`: `face_landmarker` (float16/1, 3.8 MB),
  `hand_landmarker` (float16/1, 7.8 MB), `pose_landmarker_full` (float16/1, 9.4 MB; `_lite` 5.8 MB on
  phones), `holistic_landmarker` (float16/latest, 13.7 MB). Wasm 11.7 MB.
- **Local store:** every big file (both wasm files and the models) is fetched once and kept in IndexedDB
  (db `mirror-puppet-v1`, store `files`, key = URL). The wasm is handed to MediaPipe as `blob:` URLs in a
  hand-made fileset `{ wasmLoaderPath, wasmBinaryPath }`; models go in as `baseOptions.modelAssetBuffer`.
  Google serves the models with `Cache-Control: max-age=3600`, phones evict caches — that is why.
  Bump the db name (`-v2`) to force a re-download. If the stored wasm fails inside MediaPipe the engine
  retries once with `FilesetResolver.forVisionTasks(CDN)`.

## Architecture (sections inside the file, top to bottom)

constants → local store → recognition engines → derived torso → 3D scene → coordinates & smoothing →
puppet update → 2D overlay → expression bars → `present()` → engine management → camera → controls → loop.

- **Engines** all return one shape: `{ face, blend, pose, poseWorld, hands: [{ side: 'L'|'R', attached, img, world }] }`.
  `sep` = three separate landmarkers (face, hand, pose); `holistic` = `HolisticLandmarker`.
  Menu keys: `sep:GPU`, `holistic:GPU`, `sep:CPU`, `holistic:CPU`; "automatic" tries `sep:GPU → sep:CPU → holistic:CPU`.
- **Hands ↔ wrists:** with separate models a hand is tied to the nearest pose wrist in image space
  (greedy, threshold 0.12 of the frame width); the handedness label is only a fallback for colour.
- **Coordinates.** Image landmarks: x, y in 0..1 of the frame, z in x units, smaller = closer.
  World landmarks (body, hands): metres, axes like the image, hip origin. Scene: x right, y up, z toward
  the viewer; mirror mode flips x (`deltaToScene`, `imgToScene`).
  Body: anchored at the shoulder midpoint placed by its image position; scale = metres per frame width
  read off the shoulders (world / image distance). Hands: world deltas from the wrist, attached at the
  pose wrist. Face: image points scaled by the pupil distance (63 mm), anchored at the pose nose (or by
  image position without a body). Exponential smoothing per point, slider 0..90 %.
- **Derived torso** (the pose model has no neck/chest): neck root = chin + 0.55·(chin − forehead) +
  0.5·(head centre − nose tip); clavicles root → shoulders 11/12; neck root → chin; spine root → pelvis
  (mid 23/24). Without a face mesh the same from pose eyes/mouth/ears/nose. `torsoFromFace` /
  `torsoFromPose` serve both the 2D overlay (image coords) and the 3D puppet (scene coords).
  The shoulder-to-shoulder bar and side torso lines were removed on purpose (owner's reference rig).
- **UI.** Header with toggles (Face, Hands, Body, Mesh, Mirror, Video), Smoothing, Engine, Snapshot.
  Cards (`showCard`) for errors and camera problems: they cover only the panes, never the header, and
  always offer a way out. Status line: engine · fps · size · sticky note (15 s).
  Phone layout (≤ 760 px): Settings fold behind a button; **one view at a time** (Puppet / Camera button);
  the picture is never cropped (`object-fit: contain`, box sized by `--ar`); expression panel below the
  picture. Expression panel is collapsible and **closed by default** (one summary line).
  Back camera is never mirrored (`setMirror(!back)` from `track.getSettings().facingMode`); a Flip
  button on phones switches front/back.

## Known facts and traps (verified 2026-09-11)

1. `HolisticLandmarker` on GPU in VIDEO mode fails with `outputFaceBlendshapes: true`
   ("No support of const" in the blendshapes subgraph). `holistic:GPU` therefore runs without
   expressions; the panel says so.
2. The owner's iPhone (Messenger in-app browser) delivers **landscape 1280×720 frames** even in portrait
   and even when portrait was requested. Phones now ask for 1280×960 (4:3). `object-fit: cover` was
   rejected by the owner ("looks zoomed") — keep `contain`.
3. A stream can report **2×2** at `loadedmetadata`; `syncSize()` re-reads the size on `loadedmetadata`,
   on the video `resize` event and every frame; frames narrower than 32 px are skipped.
4. `detectForVideo` timestamps must strictly increase (`lastTs` guard).
5. Chrome's headless profile caches pages served by a plain Python server — the test server sends
   `Cache-Control: no-store` and each run should use a fresh `--user-data-dir`.
6. A camera card must not be swept away when the models finish loading (`ui.loading.dataset.kind`).

## Open ideas (not started, his decision pending on the first)

- **Dogs and cats.** No MediaPipe model exists. Realistic path: an AP-10K animal-pose network (17 joints,
  e.g. RTMPose-m from mmpose) plus a cat/dog detector, both as ONNX in onnxruntime-web (WebGPU/WASM);
  ~40 MB more, slower on phones; conversion needs a Python/PyTorch setup. He was asked, no answer yet.
- Export the face mesh of one frame as OBJ (478 vertices, tessellation triangles) for 3ds Max — one button.
- Several people at once (`numPoses > 1`, per-person hand/face assignment).
- Heavy offline models (WHAM / 4D-Humans → FBX for Unreal): a Python project on the laptop, not this page.

## How to deploy

Edit `mirror-puppet.html`, commit, `git push origin main`. GitHub Pages rebuilds in ~1 minute; confirm
with `curl -s https://nikolovarch01-cmd.github.io/mirror-puppet/mirror-puppet.html | grep <new string>`.
The repo is the owner's (`nikolovarch01-cmd`); GitHub CLI 2.100 is installed and logged in on his laptop.

## How to verify without a camera

`tools/README.md` — headless Chrome with a fake camera, a harness page that injects a synthetic figure and
posts PNGs of both canvases to a tiny Python server, a phone-size run (390×844, mobile user agent).
